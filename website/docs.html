01 / Quickstart

Connect without rewriting the pipeline.

Install the SDK beside the enterprise code, attach it once at startup, then wrap the execution you want to investigate. The decorated functions keep their original behavior.

pipeline-autopsy-sdkv0.1.0 · connector package
quickstart.pyminimal setup
# install the connector from the SDK package
$ pip install -e ./sdk

# connect once, at application startup
import pipeline_autopsy as autopsy

autopsy.attach(
    api_key="your-api-key",
    pipeline="insurance-claims-v1",
    collector_url="http://localhost:8000",
)
pipeline.pytrace the stages
@autopsy.trace_step("extraction")
def extract(ocr_output: dict) -> dict:
    return build_claim_fields(ocr_output)

with autopsy.execution(claim_id="CLM-2841"):
    ocr_output = run_ocr(claim)
    fields = extract(ocr_output)
02 / API surface

Four primitives are enough to start.

The connector keeps the integration small: attach a client, mark an execution, decorate steps, and check whether the client is connected.

attach(...)
Point the SDK at a collector.Call once at startup with an API key, pipeline name, and optional collector URL.
execution(...)
Mark one pipeline run.Provides an execution ID and claim ID to every traced step through context variables.
trace_step(...)
Report a function as a stage.Captures inputs, outputs, timing, status, errors, and step order while preserving the function signature.
is_attached()
Check connector state.Returns whether the process has an active collector client.
03 / Trace lifecycle

Every execution becomes a checkable path.

Autopsy receives the run asynchronously, reconstructs the actual order, and only then looks for the first unsupported output.

01

Attach

Configure the collector once. Business logic stays where it is.

02

Capture

Decorated stages report their input, output, timing, and status.

03

Reconstruct

Execution relationships and step indexes rebuild the path that ran.

04

Diagnose

The first unsupported output becomes the root cause, not its propagation.

04 / Trace contract

The collector receives evidence, not instructions.

The SDK sends a stable JSON event for each traced stage. The Autopsy service uses that contract to build a complete investigation view.

FieldWhat it carries
execution_idThe identifier for one complete pipeline run.
claim_idThe business reference associated with the run.
step / step_indexThe stage name and its position in the execution order.
input / outputStage context used to check whether an output is supported.
started_at / ended_atTiming data for latency and sequence reconstruction.
status / errorSuccessful or failed stage state, with the error when relevant.
05 / Safety model

Observability should never become a new failure mode.

Trace delivery is best effort. If the collector is slow, unavailable, or unreachable, the SDK logs the gap and lets the enterprise function return normally.

Unplug testBefore autopsy.attach() is called, every @trace_step wrapper passes directly through to the original function. Connecting Autopsy changes what you can see, not what your pipeline does.
